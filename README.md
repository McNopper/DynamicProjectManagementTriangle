# The Dynamic Project Management Triangle

*by Norbert Nopper*

A manager's guide to the project management triangle, extended with an
explicit Fixed/Variable configuration map and a named pivoting procedure.

## Overview

The **Project Management Triangle** — scope, time, cost as interdependent
constraints — is a well-established model in the project management
literature (Barnes, 1969; Kerzner, 2017; PMI, 2017). The individual
ingredients of this document are not new. What is offered here is a
**novel synthesis** in three parts:

1. **A unified Fixed/Variable configuration map.** Each constraint is
   classified as either **Fixed (F)** or **Variable (V)** at any point in
   time. All $2^3 = 8$ binary assignments are enumerated, the two
   degenerate cases (all-fixed, all-variable) are identified as
   non-viable, and the six valid configurations are aligned with
   established delivery patterns under a method-agnostic vocabulary.

2. **Explicit, named configuration pivoting.** The deliberate
   re-assignment of F/V status, **anchored to the current actual values**
   of scope, time, and cost at the moment of re-configuration — not to
   the original baseline. Naming the action and the anchor is the
   contribution; the practice itself has analogues in rolling-wave
   planning, re-baselining (PMI, 2017), and Scrum's inspect-and-adapt
   cycle (Sutherland & Schwaber, 2020).

3. **Intentionality as an explicit management decision.** The F/V
   assignment is treated as a first-class, openly negotiated decision
   rather than an emergent property of execution.

**Status.** This is a practitioner-oriented synthesis, not a peer-reviewed
empirical study. No quantitative validation is offered. The document is
intended as a manager's reference: a vocabulary and a procedure, not a
proof.

## Diagrams

The triangle diagrams are kept in `figures/` as both SVG (for web rendering)
and PDF (for LaTeX inclusion), generated by a single Python script:

```sh
python scripts/gen_images.py
```

The script regenerates all SVG and PDF figures in one pass. See
[`scripts/README.md`](scripts/README.md) for details.
